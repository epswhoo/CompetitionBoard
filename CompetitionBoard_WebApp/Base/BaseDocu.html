Technische Dokumentation

Base

Gemeinsame Vertrags- und Modellschicht des CompetitionBoards: drei Interfaces (IDBSvc, IRnHsRepo, ITitleRepo) beschreiben den Zugriff auf Datenbank, Starterliste und Titel, drei Modelle (RnH, RnHStatus, DBConnectionSettings) transportieren die Daten. Das Projekt selbst liefert keine Implementierung — diese liegt in den Nachbarprojekten DBSvcs und Repos. Fehler werden als Klartext (string) über das Event ErrorRised gemeldet.

.NET 10 Nullable disable 3 Interfaces · 2 Modelle · 1 Enum keine Abhängigkeiten
00

Übersicht

Base liegt unter Base/Base und enthält ausschließlich öffentliche Interfaces und Datenmodelle — keine Logik, keine ProjectReference und keine PackageReference. Es ist damit das unterste Projekt der Solution: DBSvcs und Repos referenzieren Base, nie umgekehrt. Ein „RnH“ steht für Reiter und Pferd, also einen Eintrag der Starterliste einer Prüfung. Die konkreten Implementierungen werden hier nur so weit beschrieben, wie es zum Verständnis des Vertrags nötig ist.

01

Architektur & Ablauf

Die Interfaces aus Base bilden zwei Ebenen: IRnHsRepo und ITitleRepo sind die fachlichen Einstiegspunkte für die Anwendung, IDBSvc ist die darunterliegende Persistenzschicht. Die Repositories aus Repos implementieren die fachlichen Interfaces und greifen selbst nur über IDBSvc auf die Datenbank zu; DBSvc aus DBSvcs implementiert IDBSvc mit Entity Framework Core gegen SQL Server.

03

Verwendung im Code

Dieses Kapitel begleitet einen aufrufenden Svc vom Verbinden mit der Datenbank über Titel, Starterliste, Einfügen & Löschen und das Speichern einzelner Werte bis zur Fehlerbehandlung. Wo das Verhalten über den reinen Vertrag hinausgeht, ist die bestehende Implementierung (RnHsRepo, DBSvc) genannt.

03.01Datenbank verbinden (DBConnectionSettings)

DBConnectionSettings ist ein reines Datenmodell mit vier Properties ohne eigene Validierung. IDBSvc.SetDBSettings übernimmt die Daten und liefert zurück, ob eine Verbindung möglich ist. DBSvc baut daraus einen SQL-Server-Connection-String (Data Source, Initial Catalog, User ID, Password, TrustServerCertificate=True) und prüft ihn mit CanConnect().

PropertyTypBedeutung
ServerstringHostname bzw. Instanz des SQL Servers.
DBstringName der Datenbank.
UsernamestringBenutzername für die Authentifizierung.
PasswordstringPasswort für die Authentifizierung.
 
// Beispiel — dbSvc ist eine beliebige IDBSvc-Implementierung
DBConnectionSettings settings = new DBConnectionSettings
{
    Server = "localhost",
    DB = "CompetitionBoard",
    Username = "sa",
    Password = "geheim"
};
bool connected = dbSvc.SetDBSettings(settings);

03.02Titel speichern & laden (ITitleRepo)

ITitleRepo kapselt genau einen Text — den Titel der Anzeige. Save gibt den gespeicherten Titel zurück, Load den aktuell gespeicherten (oder einen leeren String), Clear speichert einen leeren Titel. TitleRepo leitet die Aufrufe an IDBSvc.TitleSave/TitleLoad weiter. 

// Beispiel
titleRepo.Save("Dressurpferdeprüfung Kl. L");
string title = titleRepo.Load();

03.03Starterliste anlegen

SetNewRnHs(string str) ersetzt die komplette Starterliste. str ist eine kommagetrennte Liste von Pferdenummern; die Reihenfolge im String bestimmt Order (beginnend bei 1). In RnHsRepo werden dabei zuerst alle bestehenden Einträge gelöscht. Nicht-numerische Einträge führen zu einem Fehler über ErrorRised und dem Rückgabewert null. 

// Beispiel — erzeugt drei RnH mit Order 1, 2, 3
IEnumerable<RnH> rnhs = rnhsRepo.SetNewRnHs("12, 7, 33");

// Aktuelle Liste lesen
foreach (RnH rnh in rnhsRepo.ReadAll().OrderBy(r => r.Order))
{
    Console.WriteLine($"{rnh.Order}. Pferd {rnh.HorseNo} — {rnh.Status}");
}

// Liste komplett leeren
rnhsRepo.DeleteAll();

03.04Einfügen & Löschen

InsertNewWithOrder(int order) fügt einen leeren Eintrag an Position order ein; alle Einträge ab dieser Position rücken um eins nach hinten. Erlaubt sind Positionen von 1 bis „letzte Position + 1“. Delete(RnH rnh) entfernt einen Eintrag und lässt alle nachfolgenden um eins nach vorn rücken — die Order-Werte bleiben so lückenlos. 

// Neuen Starter an Position 2 einfügen, anschließend Pferdenummer setzen
RnH neu = rnhsRepo.InsertNewWithOrder(2);
neu.HorseNo = 21;
rnhsRepo.SaveHorseNo(neu);

// Starter wieder entfernen
rnhsRepo.Delete(neu);

03.05Einzelwerte speichern

Neben Save(RnH), das alle Felder schreibt, bietet IRnHsRepo für jedes änderbare Feld eine eigene Methode. Die Methoden lesen den gespeicherten Eintrag anhand der Id, übernehmen das jeweilige Feld aus dem übergebenen Objekt und prüfen den resultierenden Stand gegen die fachlichen Regeln unten.

MethodeÜbernimmt Feld
SaveHorseNo(RnH)HorseNo
SaveStatus(RnH)Status
SaveMark(RnH)Mark
SaveIsDisqualificated(RnH)IsDisqualificated
SaveIsRanked(RnH)IsRanked

RnHsRepo prüft vor dem Speichern folgende fachliche Regeln. Bei einem Verstoß wird jede verletzte Regel über ErrorRised gemeldet, nichts gespeichert und null zurückgegeben:

RegelMeldung (gekürzt)
Mark zwischen 0 und 10„Note … nicht erlaubt.“
Note nur bei CompetitionDone„… die Prüfung noch nicht abgeschlossen hat.“
Keine Note bei Disqualifikation„… in dieser Prüfung disqualifiziert sind.“
Disqualifikation nur bei CompetitionDone„… kann nicht disqualifiziert werden …“
Nicht zugleich platziert und disqualifiziert„… in dieser Prüfung platziert wurden.“
Platzierung nur mit Note„… nicht bewertet wurden.“
 
// Beispiel — Prüfung beenden, dann Note vergeben
rnh.Status = RnHStatus.CompetitionDone;
rnhsRepo.SaveStatus(rnh);

rnh.Mark = 7.4;
RnH saved = rnhsRepo.SaveMark(rnh);
if (saved == null)
{
    // Regel verletzt oder DB-Fehler — Meldung kam über ErrorRised
}
Nur ein Feld — Die Save…-Einzelmethoden schreiben den gespeicherten Datenbankstand, in dem nur das jeweilige Feld ersetzt wurde. Andere Felder des übergebenen Objekts werden ignoriert; eine parallel geänderte Note wird z. B. durch SaveStatus nicht überschrieben. Existiert die Id nicht, wird „Reiter und Pferd mit Id … nicht gefunden.“ gemeldet und null zurückgegeben.

03.06Fehler behandeln (ErrorRised)

Fehler werden nicht als Exception an den Aufrufer weitergegeben. Stattdessen löst die Implementierung ErrorRised mit dem Fehlertext aus und liefert den Standardwert des Rückgabetyps — null für RnH, string und Listen, false für bool. Rückgabewerte sollten deshalb immer auf null/false geprüft werden. Anders als bei Messengers ist der Fehler hier ein einfacher string (EventHandler<string>), kein Errors.Error mit Fehlercode.

ErrorRised ist sowohl in IDBSvc als auch in IRnHsRepo deklariert. Über IRnHsRepo.ErrorRised kommen die fachlichen Meldungen aus 03.05, ungültige Eingaben und Positionen, Exceptions aus dem Repository sowie — weitergeleitet — alle Meldungen des verwendeten IDBSvc. Aufrufer, die IRnHsRepo nutzen, abonnieren deshalb nur dieses Event. 

// Beispiel — direkt nach dem Erzeugen registrieren
dbSvc.ErrorRised += (sender, message) =>
{
    Console.WriteLine($"DB-Fehler: {message}");
};
rnhsRepo.ErrorRised += (sender, message) =>
{
    Console.WriteLine($"Fehler: {message}");
};
