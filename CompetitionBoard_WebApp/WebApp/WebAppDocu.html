WebApp

Blazor-Server-Anwendung der Anzeigetafel. Sie läuft als Windows-Dienst CompetitionBoard, liest die Starterliste über IRnHsRepo und ITitleRepo und stellt sie im Browser dar. Die Bedienung ist durch Passwörter geschützt, ein eigener Port liefert eine reine Anzeige ohne Bedienelemente.

.NET 10 · Blazor Server Bedienung :5080 Anzeige :5081 MSTest + bUnit
00

Übersicht

WebApp liegt unter WebApp/WebApp und hängt von Base, DBSvcs und Repos ab. Jede Browser-Verbindung (Blazor-Circuit) bekommt über Scoped-Registrierung ein eigenes DBSvc, eigene Repositories und einen eigenen BoardSvc, der den Zustand der Tafel hält und per Timer aktualisiert. Die Oberfläche wird ohne Prerendering interaktiv gerendert.

01

Bedienung & Anzeige

Kestrel lauscht auf zwei Endpunkten. Welcher Port eine Seite ausgeliefert hat, entscheidet darüber, ob bedient werden darf. Beide Ports liefern dieselbe Anwendung und dieselben Daten.

EndpunktPortPasswortabfrageBedienelemente
Kestrel:Endpoints:Http5080ja, sobald ein Passwort gesetzt istalle; Admin zusätzlich „Passwort ändern“
Kestrel:Endpoints:Display5081 (UI:DisplayPort)neinkeine

Ablauf

  1. App.razor wird statisch gerendert und hat Zugriff auf den HttpContext. Es vergleicht Connection.LocalPort mit UI:DisplayPort (PasswordCheck.IsDisplayPort).
  2. Das Ergebnis geht als Parameter IsDisplayOnly an die interaktive Root-Komponente Routes. Blazor schützt die Parameter von Root-Komponenten mit Data Protection; der Browser kann den Wert nicht verändern.
  3. Routes.razor reicht ihn als benannten CascadingValue („IsDisplayOnly“) an die Seiten weiter.
  4. Home.razor ruft bei true BoardSvc.SetDisplayOnly() auf, überspringt die Passwortabfrage und rendert keine Schaltflächen. BoardSvc lässt den Bearbeitungsmodus danach nicht mehr zu, auch nicht über einen direkten Aufruf.
Hinweis — Wird der Port der Anzeige geändert, müssen Kestrel:Endpoints:Display:Url und UI:DisplayPort übereinstimmen. Mit UI:DisplayPort = 0 gibt es keinen Anzeige-Port; der Endpunkt sollte dann entfernt werden.
02

Passwörter

Die Bedienung auf Port 5080 ist durch zwei Passwörter aus UI:Password und UI:AdminPassword geschützt. Die Prüfung findet nicht per Cookie statt, sondern im Zustand der Blazor-Verbindung. Dadurch wird bei jedem Seitenaufruf neu gefragt, und es gibt kein Anmelde-Cookie, das auf einem Gerät liegen bleibt.

02.01Abfrage je Seitenaufruf

Home.razor startet mit AccessLevel.Locked und rendert statt der Tafel die LoginView. Jeder Seitenaufruf, jedes Neuladen und jeder neue Tab erzeugt einen neuen Circuit und damit eine neue, gesperrte Home-Instanz. Ein kurzer Verbindungsabbruch mit automatischem Wiederverbinden behält den Circuit und damit die Anmeldung.

  • Solange gesperrt ist, wird BoardSvc.StartAsync() nicht aufgerufen: keine Datenbankverbindung, kein Timer.
  • Die Schaltflächen und Eingabefelder der Tafel werden gar nicht gerendert. Blazor nimmt nur Ereignisse für gerenderte Elemente an, ein gesperrter Circuit kann also nichts ändern.
  • Nach einem falschen Passwort wartet LoginAsync eine Sekunde, um Durchprobieren zu bremsen.
  • Die Vergleiche laufen über CryptographicOperations.FixedTimeEquals.
  • Sind beide Passwörter leer (PasswordCheck.IsLockEnabled = false), entfällt die Abfrage.

PasswordCheck.GetAccessLevel prüft zuerst das Admin-Passwort. Ein leeres konfiguriertes Passwort passt nie, auch nicht zu einer leeren Eingabe.

02.03Passwort ändern

Nur ein Admin sieht den Schlüssel-Knopf (images/key.svg). Er öffnet ein Fenster mit zwei Feldern. PasswordCheck.ValidateNewPassword lehnt ab:

FallMeldung
leer„Das Passwort darf nicht leer sein.“
Wiederholung weicht ab„Die Passwörter stimmen nicht überein.“
gleich dem Admin-Passwort„Das Passwort darf nicht dem Admin-Passwort entsprechen.“
Datei nicht schreibbar„Das Passwort konnte nicht gespeichert werden: …“

Das neue Passwort gilt ab der nächsten Anmeldung; bereits angemeldete Verbindungen bleiben angemeldet. Das Admin-Passwort lässt sich nur in der appsettings.json ändern (danach Dienst neu starten). Auf kleinen Bildschirmen steht das Fenster mittig im Display statt unter dem Knopf.

02.04Speicherung

PasswordStore (Singleton) schreibt das neue Passwort nach UI:Password in die appsettings.json im Content-Root, also neben WebApp.exe. Die Datei wird mit System.Text.Json.Nodes gelesen und eingerückt zurückgeschrieben; alle anderen Einträge bleiben erhalten, fehlt der Abschnitt UI, wird er angelegt.

Die Konfiguration lädt appsettings.json bei Änderungen selbst nach. Home und ChangePasswordView lesen deshalb über IOptionsMonitor<UIConfig>.CurrentValue, damit das neue Passwort ohne Neustart gilt.

Achtung — Wird UI__Password als Umgebungsvariable gesetzt, überdeckt sie die Datei; ein in der Tafel geändertes Passwort hat dann keine Wirkung.

02.05Sicherheitsgrenzen

  • Die Passwörter stehen im Klartext in der appsettings.json (wie auch das Datenbank-Passwort).
  • Die Anwendung läuft über HTTP; Passwörter gehen unverschlüsselt durchs Netz.
  • Der Schutz richtet sich gegen unbefugtes Bedienen am Turnierplatz, nicht gegen jemanden, der den Netzwerkverkehr mitliest oder Zugriff auf den Rechner des Dienstes hat.
  • Die Anzeige auf Port 5081 ist für jeden im Netz offen; sie zeigt aber nur, was ohnehin auf der Tafel steht.
03

Konfiguration

Alle Einstellungen stehen in appsettings.json. Als Windows-Dienst ist der Content-Root das Verzeichnis der WebApp.exe (Program.cs setzt ihn, weil das Arbeitsverzeichnis eines Dienstes C:\Windows\System32 ist). 

{
  "Kestrel": {
    "Endpoints": {
      "Http":    { "Url": "http://0.0.0.0:5080" },
      "Display": { "Url": "http://0.0.0.0:5081" }
    }
  },
  "Db": { … },
  "UI": {
    "EditTime": 15,
    "RefreshTime": 2,
    "DisplayPort": 5081,
    "Password": "",        // Bedienung, änderbar in der Tafel
    "AdminPassword": ""    // nur hier änderbar
  }
}
EinstellungBedeutungStandard
UI:DisplayPortPort ohne Bedienelemente und ohne Passwort; 0 = keiner.5081
UI:PasswordPasswort der Bedienung. Leer und AdminPassword leer = kein Schutz.leer
UI:AdminPasswordAdmin: Bedienung plus Ändern von UI:Password.leer
UI:RefreshTime / EditTimeSekunden zwischen zwei Aktualisierungen, normal bzw. im Bearbeitungsmodus.2 / 15

Die Bedienungsanleitung in der App (wwwroot/docu/Bedienungsanleitung.html) beschreibt die Passwörter bewusst nicht.

04

Installation & Update

WebApp/install-service.ps1 installiert oder aktualisiert den Dienst. Es muss als Administrator laufen.

  1. dotnet publish nach %TEMP%\CompetitionBoard_publish.
  2. Dienst stoppen, falls er läuft.
  3. Beide Passwörter aus der installierten appsettings.json merken.
  4. Alles nach %ProgramFiles%\CompetitionBoard kopieren (die appsettings.json wird dabei überschrieben).
  5. Fehlt ein Passwort, fragt das Skript danach (leer = keins). Danach schreibt es Endpunkte, DisplayPort und beide Passwörter in die installierte appsettings.json.
  6. Dienst anlegen bzw. Pfad setzen, Starttyp Manuell.
  7. Firewall-Regeln für beide Ports anlegen oder aktualisieren, Dienst starten, erreichbare Adressen ausgeben.
Browser-Cache — Statische Dateien werden bis zu einer Stunde gecacht. Das Icon von „Passwort ändern“ wird über @Assets["images/key.svg"] mit Prüfsumme im Namen eingebunden und daher nach einem Update sofort neu geladen.
