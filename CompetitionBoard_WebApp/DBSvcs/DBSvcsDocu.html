DBSvcs

Persistenzschicht des CompetitionBoards: DBSvc implementiert IDBSvc aus Base mit Entity Framework Core gegen SQL Server. Das Projekt speichert die Starterliste (RnH) und den Titel der Anzeige. Fehler werden nicht geworfen, sondern als Text über ErrorRised gemeldet; die Methode liefert dann den Standardwert ihres Rückgabetyps.

.NET 10 Nullable disable EF Core 10.0.12 SQL Server keine Tests
00

Übersicht

DBSvcs liegt unter DBSvcs/DBSvcs und referenziert nur Base sowie die NuGet-Pakete Microsoft.EntityFrameworkCore und Microsoft.EntityFrameworkCore.SqlServer. Nach außen zählt eigentlich nur DBSvc; CompetitionBoardDBContext und TitleDBContextModel sind zwar public, werden aber nur intern verwendet. Die Helfer unter Helpers/ sind internal. In der WebApp wird DBSvc als Scoped registriert, also eine Instanz pro Browser-Verbindung.

01

Architektur & Ablauf

DBSvc speichert nur den Connection-String. Jede Methode erzeugt über CreateDBContext() einen eigenen, kurzlebigen CompetitionBoardDBContext und gibt ihn am Ende wieder frei (using). Dadurch sieht jeder Aufruf den aktuellen Datenbankstand, es bleiben keine Kontexte liegen, und parallele Aufrufe teilen sich keinen Kontext. Alle öffentlichen Methoden laufen durch TryCatchException, das Exceptions in ErrorRised umwandelt.

03

Verwendung im Code

DBSvc hat einen parameterlosen Konstruktor. Vor jedem anderen Aufruf muss SetDBSettings einmal gelaufen sein, sonst meldet jede Methode „Es sind keine Datenbankeinstellungen gesetzt.“. Im Normalfall wird DBSvc nicht direkt benutzt, sondern als IDBSvc an RnHsRepo und TitleRepo übergeben.

03.01Verbinden

SetDBSettings baut aus DBConnectionSettings mit einem SqlConnectionStringBuilder den Connection-String und prüft mit Database.CanConnect(), ob die Datenbank erreichbar ist. Sonderzeichen wie ; im Passwort werden dabei korrekt maskiert. Der Verbindungs-Timeout beträgt 5 Sekunden, ein nicht erreichbarer Server blockiert den Aufruf also höchstens so lange. CheckConnection() prüft die Verbindung später erneut. 

// Aufbau des Connection-Strings (DBConnectionStringHelpers)
DataSource = Server, InitialCatalog = DB, UserID = Username, Password = Password,
TrustServerCertificate = true, ConnectTimeout = 5

// Beispiel
IDBSvc dbSvc = new DBSvc();
dbSvc.ErrorRised += (sender, message) => Console.WriteLine(message);

bool connected = dbSvc.SetDBSettings(new DBConnectionSettings
{
    Server = "localhost",
    DB = "CompetitionBoard",
    Username = "sa",
    Password = "geheim"
});

03.02Lesen

ReadAll() liefert alle Einträge nach Order sortiert, ReadById(id) einen einzelnen Eintrag. Beide geben vom Kontext losgelöste Objekte zurück; Änderungen daran wirken sich erst aus, wenn sie über Save gespeichert werden. Existiert die Id nicht, meldet ReadById „Reiter und Pferd mit Id … nicht gefunden.“ und liefert null. 

IEnumerable<RnH> starter = dbSvc.ReadAll();   // sortiert nach Order
RnH einer = dbSvc.ReadById(17);

03.03Einfügen, Speichern, Löschen

MethodeAblaufRückgabe
Insert(RnH)Kopiert alle Felder in ein neues Objekt, setzt dessen Id auf 0, fügt es ein und schreibt die vergebene Id zurück in das übergebene Objekt.das übergebene Objekt mit Id
Save(RnH)Lädt den Eintrag per Id, übernimmt alle Felder und speichert.das übergebene Objekt
Delete(RnH)Lädt den Eintrag per Id, entfernt ihn und prüft danach, dass er nicht mehr existiert.true wenn gelöscht

Bei unbekannter Id melden Save und Delete „Reiter und Pferd mit Id … nicht gefunden.“ und liefern null bzw. false. 

// Beispiel
RnH neu = dbSvc.Insert(new RnH { HorseNo = 12, Order = 1 });   // neu.Id ist jetzt gesetzt
neu.Status = RnHStatus.OnWarmUpField;
dbSvc.Save(neu);
dbSvc.Delete(neu);

03.04Titel

TitleLoad() liefert den Titel der ersten Zeile von TitleTable oder einen leeren String. TitleSave(title) überschreibt den Titel dieser Zeile (bzw. legt sie an) und gibt ihn zurück. 

dbSvc.TitleSave("Dressurpferdeprüfung Kl. L");
string title = dbSvc.TitleLoad();

03.05Fehler behandeln (ErrorRised)

Jede öffentliche Methode ist in TryCatchException gekapselt. Tritt eine Exception auf, wird ErrorRised mit sender = this und ex.Message ausgelöst und der Standardwert zurückgegeben (null bzw. false). Fehlende Einstellungen und unbekannte Ids werden mit eigenen deutschen Meldungen gemeldet; alle übrigen Meldungen stammen direkt aus EF Core bzw. dem SQL-Client. 

private T TryCatchException<T>(Func<T> todo)
{
    try { return todo(); }
    catch (Exception ex)
    {
        ErrorRised?.Invoke(this, ex.Message);
        return default;
    }
}

Code-Review

Ergebnis der Durchsicht des Quellcodes. Die Befunde wurden korrigiert; offen sind nur noch die Punkte in der zweiten Tabelle.
